# Split storage repositories and basic CRUD

## Intent and approval

The user approved option 2: separate repositories per entity, rather than one
repository containing all persistence operations. This supports incremental Go
learning and makes each entity's persistence easier to change independently.

## Approaches

1. Split files while retaining one Repository: smallest diff, but one object still
   owns every persistence responsibility.
2. Separate WorkspaceRepository, IntegrationRepository, ThreadRepository,
   MessageRepository and ThreadLinkRepository in the existing storage package:
   selected by the user. Share one PostgreSQL pool, not one connection per object.

## Scope and constraints

- Add Create/Get/List/Update/Delete for the five existing entities, handwritten
  SQL in db/query and generated sqlc methods. Preserve the current schema.
- Keep domain types independent of pgx/sqlc. Comments and documentation are English.
- No generic CRUD framework, new HTTP API, ingest wiring, credential management,
  UUID generator, vector search, database selector or applied Supabase migration.
- UUIDs are supplied by callers. Validate their syntax at the repository boundary;
  UUIDv7 generation remains the caller's responsibility, not a storage feature.
- Workspace operations are trusted administrative operations. Every child-entity
  lookup/write takes workspace ID and scopes SQL accordingly. The application must
  still authorize callers; knowing a workspace ID is not authorization.
- Preserve restrictive foreign keys. Never cascade-delete or rewrite ownership,
  source identities, message authors or timestamps through ordinary updates.
- Map absent rows to entity-specific domain errors; wrap other errors with an
  operation label and preserve their causes. Lists return an empty slice on no rows.
- Credentials must not be selected into ordinary integration results or overwritten
  by integration updates. Maps are JSON objects; nil input maps mean empty objects.

## Repository contracts (implementation choices)

Each repository has its own file and constructor receiving the shared
*pgxpool.Pool. It holds sqlc.New(pool); MessageRepository additionally uses pool
transactions and sqlc.WithTx. Constructors reject a nil pool. Common mapping and
input conversion live in mapping.go; no common repository object remains.

Create/update input structs contain only writable fields; returned values are
domain entities. Updates replace the documented mutable fields (not PATCH).
Lists take limit and offset, require limit 1..100 and nonnegative offset, and use
stable ordering. Source identity is immutable after insertion.

| Repository | Create fields, excluding DB-owned timestamps | Mutable fields | List boundary/order |
| --- | --- | --- | --- |
| Workspace | ID, DisplayName | DisplayName | trusted admin; updated_at DESC, id DESC |
| Integration | ID, WorkspaceID, Platform, Role, Config, IsEnabled | Role, Config, IsEnabled | workspace; created_at DESC, id DESC |
| Thread | ID, WorkspaceID, IntegrationID, ExternalScope, ThreadType, ExternalID, Title, Metadata | Title, Metadata | workspace; updated_at DESC, id DESC |
| Message | ThreadID, ExternalMessageID, SenderID, SenderName, SenderRole, Content, OccurredAt, Metadata | Content, Metadata | workspace + thread; id ASC |
| ThreadLink | WorkspaceID, SourceThreadID, TargetThreadID, Metadata | Metadata | workspace + either endpoint; source_thread_id, target_thread_id |

Message IDs are generated by PostgreSQL. A zero OccurredAt uses ingestion time;
nonzero source timestamps are preserved. Thread summaries start empty. Summary
generation/update is deferred to the future memory workflow, not exposed as an
unsafe generic thread update. ThreadLink has a composite key, not an invented ID.
Canonicalize link endpoints by parsed UUID bytes for every operation; reject self
links and require both endpoints in the same workspace.

## Message and summary consistency

Create/update/delete messages in a transaction that first locks the owning thread
with SELECT FOR UPDATE scoped by workspace. This serializes repository message
writes per thread before allocating message IDs. Missing parents return not found.

For update/delete, if the affected message ID is at or below the summary cursor,
clear rolling_summary and summary_through_message_id atomically with the change.
Clear the cursor before deleting its referenced message. Preserve summary for
changes strictly after the cursor. Refresh thread.updated_at for message writes;
rollback all effects on failure. Do not attempt to regenerate a summary here.

## Verification and startup

Use isolated local PostgreSQL tests, never a real Supabase project. An explicit
TEST_DATABASE_URL may opt into integration tests; never fall back to DATABASE_URL.
Test CRUD, tenant isolation, missing rows, duplicates, JSON, link symmetry,
restrictive deletes, summary invalidation and rollback. Test invalid inputs
without any database. Run full Go tests, race checks and sqlc regeneration.

Fix the existing DatabaseConfig typo as a build prerequisite. main retains pool
ownership and removes unused monolithic repository setup; do not construct unused
entity repositories or create sample rows at startup. Wire repositories only when
an actual consumer is added.
